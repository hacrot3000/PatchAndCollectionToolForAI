v6.17.0 controlled batch engine:
- failure_policy=fail_fast remains default; continue_independent continues only after a proven-safe failure;
- dependency order uses existing manifest.patch.id plus batch.depends_on; failed dependencies default to BLOCKED;
- successor after unresolved FAIL must declare batch.previous_failure action: delete/retry_before/run_after/block + reason;
- whole-batch read-only preflight runs before first source write; dependent SOURCE_DRIFT may defer until predecessor runs;
- transaction_policy=batch snapshots declared targets + selected package bytes and requeues replay packages after rollback;
- Smart Resume supports all/failed/remaining and includes PASS items rolled back by an atomic batch;
- persistent report browser supports aggregate/detail logs, filtering, source diff, support ZIP and run history management;
- native Windows runtime lane is shipped as tools/run_windows_native_tests.ps1 and must be executed on a real Windows host for a native PASS claim.

Explicitly NOT IMPLEMENTED by requirement:
- Target-overlap/conflict analyzer.
- Patch provenance / identity subsystem. Dependency uses the existing manifest.patch.id only.

PATCH execution remains IN-PLACE. SANDBOX/worktree transaction execution is permanently unsupported.
