Python Patch Tool v6.7.13 portable regression/document-contract repair

Public entry point:
  tools/run_python_patches.sh

MANDATORY COLLECT public contract:
  AI delivers one ZIP containing exactly one CODE_COLLECTION_REQUEST*.json.
  User puts that ZIP in patchs/ and runs only ./tools/run_python_patches.sh.
  Loose request JSON and manual COLLECT-subcommand guidance are obsolete/invalid. See tools/_patch_lib/docs/AI_USAGE_CONTRACT.md.
  Successful COLLECT prints exactly one highlighted [PRIMARY - UPLOAD THIS FILE] result ZIP path and validates that the reported local artifact exists and is a ZIP.

Compatibility requirement:
  Existing private core modules such as python_patch_runner.py and the readonly
  collector must already be installed. They are deliberately not reconstructed
  from incomplete evidence. The public launcher forces documented PATCH
  execution routes to the core's in-place `--transaction off` mode.

Release scope:
  Bug/regression/document-contract repair only. No new feature group is started.

v6.7.13 regression repairs:
- Destructive selector delete revalidates queue identity and refuses to unlink a replaced/symlinked same-name artifact.
- HANDOFF copy filenames such as `*_HANDOFF(1).zip` are rejected while genuine legacy `patch_*handoff*.zip` packages remain runnable.
- COLLECT result ZIP validation verifies member CRC integrity, not only the ZIP container signature.
- ZIP-specific result labels outrank generic `FILE:`/`ARTIFACT:` fallbacks so a later unrelated ZIP cannot replace the primary collection result.
- User-facing queue/progress sanitization removes Unicode bidi/format controls in addition to ANSI/C0/C1 controls.
- All prior zero-argument COLLECT, in-place/SANDBOX-removal, fail-fast, selector, classifier, and result-highlight fixes remain active.
