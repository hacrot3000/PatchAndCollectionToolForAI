Python Patch Tool v6.18.4 — hướng dẫn nhanh

1. Cài đặt / cập nhật

Linux / POSIX:

unzip -o python_patch_tool_v6.18.4.zip -d "$PWD"
cat tools/_patch_lib/VERSION

Windows PowerShell: cần Python 3.10+.

Expand-Archive -Force .\python_patch_tool_v6.18.4.zip .
Get-Content .\tools\_patch_lib\VERSION

Kết quả version phải là 6.18.4.

2. Chạy công cụ

Linux / POSIX:

./tools/run_python_patches.sh

Windows CMD hoặc PowerShell (khuyến nghị):

tools\run_python_patches.bat

Windows PowerShell trực tiếp:

.\tools\run_python_patches.ps1

Không cần tham số. Cả ba lệnh dùng cùng patchs/ và cùng core. Trên Windows console phù hợp, tool hỗ trợ menu phím mũi tên/Space tương tự POSIX; nếu console không hỗ trợ an toàn thì tự dùng menu nhập số/range.

Khi cần chẩn đoán PATCH mà không sửa source, dùng menu v hoặc lệnh validate --patch; kết quả phân biệt PATCH sai, source drift và lỗi tool.

Dùng p để preview PATCH hiện tại trên private mirror, / để tìm/lọc theo tên/id/summary/target. Dùng ./tools/run_python_patches.sh plan để xem batch plan read-only; có thể thêm --export-recipe BATCH_RECIPE.json rồi chạy lại chính xác bằng run --recipe BATCH_RECIPE.json.

PATCH có thể khai báo on_failure.commands để chạy command tự động chỉ khi execution thất bại. Command chạy sau rollback attempt, không thay thế RC/lỗi gốc của PATCH và không dùng stdin tương tác.

Nếu PATCH khai báo project.key hoặc validation.profiles, project cần cấu hình tương ứng trong .python_patch_tool.json; validation command nằm ở local config, không nằm trong PATCH.

  • PATCH: có thể chọn nhiều. POSIX TTY và Windows console hỗ trợ phím 0..9 để đặt priority khi fullscreen khả dụng; nếu fallback line selector thì dùng số/range.
  • Yêu cầu lấy source cho AI: mỗi lần chỉ chọn 1 request, không chạy chung với PATCH.
  • Tool không khóa project; bạn có thể chủ động chạy terminal khác song song.
  • Nếu nhiều PATCH trong cùng queue có checksum giống hệt nhau, tool giữ một file và tự loại file trùng.
  • Nếu nghi ngờ tool bị copy/cài thiếu hoặc sai checksum, nhấn h trong menu để kiểm tra nhanh Tool Health; thao tác này không chạy PATCH.
  • Nếu nghi ngờ COLLECT search bỏ sót source, chạy ./tools/run_python_patches.sh health-search (Windows dùng launcher tương ứng) để tự kiểm tra lớp discovery/search trên fixture tạm.
  • Khi chạy launcher không tham số, selector luôn có thêm mục HISTORY; dùng ↑/↓ + Enter để xem lại lịch sử rồi quay lại queue. Nếu queue thực sự không có PATCH/COLLECT runnable, tool in warning, AUTO STATUS: IDLE và Tool Health rồi tự mở HISTORY ở terminal tương tác; invocation này vẫn không tạo run/log và không ghi LAST_RUN/history. Nếu queue có package nhưng tất cả bị duplicate/auto-filter, tool in QUEUE CLEANUP SUMMARY và chờ Enter trước khi mở HISTORY để bạn đọc được các package đã bị loại.
  • SMART RESUME chỉ tự bật khi LAST_RUN thực sự FAIL và còn item recovery của chính run đó trong queue. Failure cũ vẫn được giữ để chặn successor liên quan nhưng không được chiếm màn hình trước PATCH/COLLECT mới độc lập.

3. Khi AI cần thêm source

AI sẽ chuẩn bị một ZIP CODE_COLLECTION_REQUEST_*.zip. Bạn chỉ cần chép ZIP vào patchs/, chạy lệnh zero-argument ở trên, sau đó upload đúng ZIP được tool đánh dấu:

!!! [PRIMARY - UPLOAD THIS FILE] !!!
>>> ACTION REQUIRED: UPLOAD TO CHATGPT / AI SERVER <<<
/path/to/CODE_COLLECTION_RESULT_....zip

Người dùng không cần tự chọn kiểu thu thập hay chỉnh JSON; AI và Patch Tool chịu trách nhiệm phần kỹ thuật đó.

4. Chuẩn bị AI trước mỗi phiên làm việc

Gửi cho AI toàn bộ file trong tools/_patch_lib/docs/, không chỉ một file. Nếu đang tiếp tục phát triển Patch Tool, gửi thêm tools/implementing.md và tools/PYTHON_PATCH_TOOL_FEATURES_VI.md.

Yêu cầu AI đọc tài liệu hiện hành trước khi tạo PATCH hoặc yêu cầu lấy source. Không cần dùng tài liệu/version cũ nếu chúng mâu thuẫn với bộ docs hiện tại.

5. Prompt mẫu chuẩn

Tiếng Việt

Tôi đang dùng Python Patch Tool hiện hành. Hãy đọc TOÀN BỘ các file tôi gửi từ tools/_patch_lib/docs/ trước khi làm việc; nếu có tools/implementing.md và tools/PYTHON_PATCH_TOOL_FEATURES_VI.md thì đọc cả hai.
Tuân thủ contract hiện tại, không dùng hướng dẫn/version cũ để suy đoán. Ưu tiên sửa lỗi trước, sau đó mới hoàn thiện task đang dở; không tự start tính năng mới.
Nếu cần source/evidence, hãy tự chuẩn bị đúng MỘT CODE_COLLECTION_REQUEST_*.zip theo tài liệu hiện hành; không trả JSON rời và không yêu cầu tôi chạy lệnh collect thủ công. Nếu cần patch code, trả đúng MỘT ZIP patch tương thích tool hiện hành.
Người dùng chạy zero-argument launcher theo OS: Linux ./tools/run_python_patches.sh; Windows tools\run_python_patches.bat (hoặc .\tools\run_python_patches.ps1). Sau FAIL_HANDOFF, PATCH successor phải khai báo rõ xử lý predecessor lỗi (delete/retry_before/run_after/block), không để PATCH mồ côi.

English

I am using the current Python Patch Tool. Read ALL files I provide from tools/_patch_lib/docs/ before doing any work; also read tools/implementing.md and tools/PYTHON_PATCH_TOOL_FEATURES_VI.md when provided.
Follow the current contract and do not infer behavior from obsolete versions. Fix bugs first, then finish already in-progress tasks; do not start new features on your own.
If source/evidence is required, prepare exactly ONE CODE_COLLECTION_REQUEST_*.zip according to the current documentation; never return loose JSON and never ask me to run a manual collect command. If a code patch is required, return exactly ONE patch ZIP compatible with the current tool.
The user runs the zero-argument launcher for the OS: Linux ./tools/run_python_patches.sh; Windows tools\run_python_patches.bat (or .\tools\run_python_patches.ps1). After a FAIL_HANDOFF, any successor PATCH must explicitly handle the unresolved predecessor (delete/retry_before/run_after/block) instead of orphaning it.

Русский

Я использую актуальную версию Python Patch Tool. Перед началом работы прочитайте ВСЕ файлы, которые я отправляю из tools/_patch_lib/docs/; если приложены tools/implementing.md и tools/PYTHON_PATCH_TOOL_FEATURES_VI.md, прочитайте и их.
Следуйте только текущему контракту и не делайте выводы по устаревшим версиям. Сначала исправляйте ошибки, затем завершайте уже начатые задачи; не начинайте новые функции самостоятельно.
Если нужны исходники/доказательства, подготовьте ровно ОДИН архив CODE_COLLECTION_REQUEST_*.zip согласно актуальной документации; не возвращайте отдельный JSON и не просите запускать collect вручную. Если нужен патч кода, верните ровно ОДИН ZIP-патч, совместимый с текущей версией инструмента.
Пользователь запускает zero-argument launcher своей ОС: Linux ./tools/run_python_patches.sh; Windows tools\run_python_patches.bat (или .\tools\run_python_patches.ps1).

6. Công cụ này làm được gì?

  • Nhận và chạy PATCH theo một quy trình thống nhất, in-place, không dùng SANDBOX/worktree.
  • Cho phép chọn nhiều PATCH và đặt thứ tự ưu tiên bằng số 0..9.
  • Tự phát hiện PATCH trùng bytes/checksum trong cùng queue, giữ một bản và loại bản dư.
  • PATCH đã có exact checksum trong lịch sử local chỉ được báo bỏ qua một lần, sau đó chuyển sang patchs/ignore/YYYY-MM-DD-<tên file gốc> nên lần chạy sau không hỏi lại.
  • Khi AI cần thêm source, tool thu thập dữ liệu read-only và chỉ rõ một ZIP cần upload lại cho AI.
  • Fail-closed với package/request không đúng contract để tránh chạy nhầm.
  • Release tự chứa runtime cần thiết cho contract hiện hành; không cần private core cũ.
  • Cuối mỗi PATCH, tên file vừa chạy được highlight lại; nếu FAIL sẽ có banner cảnh báo nổi bật, terminal hỗ trợ màu sẽ dùng nền đỏ/chữ vàng. Đường dẫn FAIL_HANDOFF/ZIP vẫn hiển thị như trước.
  • Khi chọn nhiều PATCH, cuối run có bảng PASS / FAIL / BLOCKED / PREFLIGHT_FAIL / NOT_EXECUTED / SKIPPED. Mặc định tool tiếp tục các PATCH độc lập sau một lỗi; PATCH phụ thuộc hoặc dùng chung effective target với PATCH lỗi sẽ bị BLOCKED. fail_fast vẫn có thể bật rõ ràng khi muốn dừng ở lỗi đầu tiên. Ctrl+C/rollback failure/partial-unknown vẫn safety-stop.
  • Nếu phiên trước có PATCH lỗi, Smart Resume dùng ↑/↓ + Enter và hiển thị mô tả của mục đang chọn. Có thêm COLLECT source của PATCH lỗi và Xóa PATCH lỗi khỏi hàng đợi (chuyển sang patchs/ignore). Nếu có nhiều PATCH lỗi, dùng selector checkbox với Space để chọn nhiều.
  • Log chi tiết từng PATCH và log tổng hợp batch được lưu trong artifacts/patch_tool/runs/. Mở lại bằng lệnh report; menu hỗ trợ detail, aggregate, lọc lỗi/PASS, source diff, support ZIP và history.
  • HISTORY chỉ hiện các lần có PATCH/COLLECT thực sự (ẩn IDLE), mỗi dòng hiển thị tên package → ngày giờ local của máy → trạng thái, và mặc định trỏ tới lần PASS gần nhất có công việc thực sự. Khi mở một run, report in sẵn Important files với đường dẫn tuyệt đối của COLLECT result/request ZIP, FAIL_HANDOFF, recovery/replay/archive package và log chẩn đoán quan trọng. Artifact đã bị dọn vẫn hiện vị trí lịch sử kèm [missing]; detail/log/source diff và support ZIP vẫn xem qua menu report.
  • Khi terminal tương tác hỗ trợ an toàn, lúc chạy PATCH tool giữ một live status header cố định ở trên với trạng thái WAITING / RUNNING / PASS / FAILED / BLOCKED / ... và để console cuộn bên dưới. Nếu terminal không phù hợp hoặc bị resize, tool tự fallback về console thường. Có thể tắt bằng PTV_DISABLE_LIVE_STATUS=1; log lưu trên disk luôn giữ nguyên.

7. Quy trình thông thường khi dùng cùng Chat AI

  1. Đầu phiên, gửi cho AI toàn bộ tools/_patch_lib/docs/ và dùng một prompt mẫu ở trên.
  2. Mô tả lỗi, mục tiêu hoặc task cần làm. AI đọc docs rồi phân tích.
  3. Nếu đủ thông tin, AI trả một PATCH ZIP. Chép vào patchs/ và chạy launcher zero-argument của hệ điều hành.
  4. Nếu thiếu source/evidence, AI trả một CODE_COLLECTION_REQUEST_*.zip. Chép vào patchs/ và chạy cùng lệnh.
  5. Upload đúng ZIP được đánh dấu [PRIMARY - UPLOAD THIS FILE] cho AI.
  6. Nếu PATCH FAIL và tool hiện [PRIMARY - UPLOAD THIS FILE] PATCH FAIL HANDOFF, upload ZIP đó cho AI. PATCH successor do AI tạo phải nói rõ xử lý PATCH lỗi liền trước bằng delete, retry_before, run_after hoặc block; không để PATCH lỗi mồ côi trong queue.
  7. AI dùng evidence/source mới để tạo/cập nhật PATCH. Bạn chạy lại tool; khi PASS thì tiếp tục task kế tiếp.
