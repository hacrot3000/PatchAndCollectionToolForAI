Điều hướng: [kế hoạch chung](README.md). F08.1 đã được triển khai ở mức parse/validate/preview. F08.2 đang được triển khai từng phần; chưa đủ bằng chứng để đánh dấu hoàn tất hoặc bật end-to-end execution.

## F08.1 — Markdown/canonical JSON manifest: IMPLEMENTED (planning-only)

Package `internal/taskmanifest` parses bounded Markdown and strict versioned canonical JSON into a deterministic manifest. It validates project binding, IDs, duplicate IDs, unknown/self/duplicate dependencies, cycles, acceptance warnings, count/input limits, and reports roots/blocked/topological preview. `POST /api/agent/task-manifests/validate` derives the active project ID server-side, checks permission, performs no provider call, writes no file/task and invokes no executor. The Agent Chat UI accepts Markdown or canonical JSON, renders issues/graph preview, and permits download of valid canonical JSON. `planning_only:true` and `execution_enabled:false` are part of the response contract. No user Markdown is treated as shell/Patch instructions.

## F08.2 — Dependency DAG Scheduler: PARTIAL / IN PROGRESS (uncommitted)

Implemented foundation in `vscode_tasks_menu_go/internal/agentrun`:

- `DAGScheduler` claims tasks in topological order only when all dependencies have terminal-success, fences claims, caps configured concurrency at 5, blocks dependents on failed/unknown/interrupted prerequisites, and supports explicit retry of failed nodes. Snapshot save/load is bounded and private; active work is restored as `interrupted`, never auto-replayed.
- `Manager` persists run bindings, history snapshot reference, event journal and lifecycle in owner-private files. Global process semaphore is shared with legacy Agent Chat; per-owner Agent Chat cap is 5, and a context marker prevents nested admission from counting a Manager-owned run twice. Ambiguous failures are not retryable unless an executor classifies them safe; interrupted runs require explicit `confirm_no_side_effect` to resume.
- `ContextGroupStore` and `/api/agent/context-groups` provide owner/project-bound shared instruction groups with revision CAS. Workflow creation can pin a group ID/revision/hash; every task prompt and immutable snapshot records that revision/source ref. Updating the group later does not change an existing workflow/task snapshot.
- `SnapshotStore` persists owner/conversation/project-bound immutable context history with a hash and source refs; API creates ad-hoc snapshots at `/api/agent/context-snapshots`, and run submission requires the matching snapshot ID and external-data consent.
- `WorkspaceRegistry` verifies Git common dir/worktree listing/project identity, registers owner→execution binding per conversation/run/provider-config/scope, and creates detached worktrees from owner HEAD under private state. It never copies provider credentials. `Server.ResolveAgentRunInputs` and `AgentRunWorkspaceResolver` expose the verified owner/execution binding and snapshot to the provider payload builder.
- Run API endpoints expose submit/list/status/stop/retry/reviewed-resume, detached-worktree creation and a read-only per-run integration report (`GET /api/agent/runs/{id}/integration-report`) containing base/head, changed paths and bounded diff/status hashes. It never mutates the owner branch. Provider Router is lazily created through the owner-bound adapter factory; config version and credentials remain owner-scoped.

**Shared contract with PLAN 02:** server creates an owner-bound router via `NewAgentRunProviderExecutor(owner)`; its `ProviderResolver` pins owner principal, `RunSpec.OwnerWorkspaceID`, provider/model and `RunProviderConfigVersion` and resolves credentials only at invocation time. The payload builder verifies history against the immutable `ContextSnapshotID`, resolves physical files only through `Server.AgentRunWorkspaceResolver()` / `ResolveAgentRunInputs()`, and uses `Server.BuildAgentRunWorkspacePack()` when including curated project context so the active worktree—not the UI's current workspace—is read. Run Manager acquires the global run slot with `agentrun.AcquireGlobalSlotContext`; the context carries a live, revocable lease, and nested admission checks `agentrun.GlobalSlotHeld(ctx)` to avoid double acquisition. Plain or expired contexts cannot claim the slot. No credentials belong in `RunSpec`, context snapshots, events or worktree files.
